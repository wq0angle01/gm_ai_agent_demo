# 游戏运营操作手册

本文件面向 GM 运营人员，覆盖日常运营操作的标准流程。

## 如何发放补偿邮件

当服务器维护、Bug 修复或活动异常需要给玩家发放补偿时：
1. 确定补偿对象：全服（target_type=ALL）还是指定玩家列表（target_type=SPECIFIED）。
2. 在后台「邮件管理」创建新邮件，填写标题、正文、金币和钻石数量。
3. 指定玩家时，target_player_ids 填玩家 ID 逗号分隔（如 "1,2,3"）。
4. 创建后状态为 DRAFT，确认无误后点击「发送」。发送后不可撤回。
5. 标准补偿模板：标题"维护补偿"，正文说明原因和补偿内容，金币 1000 + 钻石 50。

## 封禁与解封操作规范

封禁是高风险操作，必须遵循以下规则：
- 封禁前必须在工单中记录证据（截图、日志、录像链接）。
- 单次封禁影响范围不超过 10 个账号，批量封禁需主管审批。
- AI 助手可以执行封禁/解封，但操作人（X-Operator）必须是已登录的运营账号。
- 所有封禁和解封操作都会记入审计日志，不可删除。
- 误封应在确认后立即解封，并通过邮件向玩家致歉。

## 公告发布流程

1. 在后台「公告管理」创建公告，填写标题、正文、优先级。
2. 优先级数值越大越靠前显示（1-100），紧急维护公告建议设为 100 并置顶。
3. 设置生效时间和过期时间（可选），过期后自动不展示。
4. 新建的公告状态为 DRAFT，确认后点击「发布」变为 PUBLISHED。
5. 已发布的公告不可重复发布，如需修改应新建一条并下线旧的。

## 道具发放标准流程

通过「道具管理」给玩家发放道具时：
1. 确认道具 code 存在于 game_item 表中（如 POTION_HP、SWORD_IRON）。
2. 使用 grant 接口指定玩家 ID 和数量。
3. 单次发放数量不超过 max_stack 限制。
4. 发放操作会记入审计日志，action 为 GRANT_ITEM。
5. 如需批量发放，建议通过邮件附件方式（邮件系统支持 gold + diamond，暂不支持道具附件）。
